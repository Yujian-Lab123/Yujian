# 遇见 · 两天极限开发与参赛交付计划

> 日期基线：2026-09-12。目标不是在两天内补齐生产级平台，而是交付一个可公开访问、可稳定演示、能让评委清楚看见 AI 价值的完整纵向切片。

## 1. 当前事实盘点

### 已完成且可以复用

- Next.js 16 + PostgreSQL + Drizzle + 独立画像 Worker 的全栈基座已存在。
- 无知乎 OAuth、无 LLM Key 时，10 个预览用户和 27 篇内容仍可跑完整流程。
- 人物画像的两阶段 Qwen 管线、证据索引、爬虫数据转换、数据库任务和前端画像页均已有实现。
- 相遇模块已有候选召回、粗排、内容桥接、对话桥接、此刻信号、单向认识意愿与双向确认。
- `/profile`、`/me`、`/side`、`/encounter` 已按独立产品模块拆开；`/about` 与统一五段导航正在整合。
- 生产依赖审计当前为 0 个已知漏洞；现有 5 组测试、12 个测试用例通过。

### 当前阻塞

- 工作树位于 `feat/d-unified-navigation`，有多批未提交前端修改混在一起，不能直接整体提交。
- 当前 `npm run typecheck` 在 `app/profile/profile-experience.tsx:325-329` 有 5 个类型错误；因此当前版本不能合并或部署。
- `lint`、测试、生产依赖审计已通过，但完整 `npm run check` 尚未通过。
- 本次 Codex 环境中的 GitHub CLI 返回 401，无法据此确认线上 PR、Issue 和分支保护状态；需要负责人在自己的终端重新确认。
- 本地 Web 当前没有运行，尚未对这批最新改动做完整浏览器视觉回归。

### 对比赛规则的判断

截图中的核心权重集中在 AI 场景价值、创新度和完成度，产品体验权重较低但会显著影响演示可信度。最优策略是优先证明：

1. AI 为什么必要，而不是只做普通社交页面；
2. 推荐为什么是这个人、为什么是这篇内容；
3. 长期画像、此刻、侧面如何真实改变相遇；
4. 从进入到双向连接是否一次跑通；
5. 页面是否足够稳定、清楚，而不是功能数量是否最多。

## 2. 两天内明确不做

- 不做站内聊天、群聊、Feed、复杂通知中心。
- 不接 Redis、向量数据库、微服务或新消息队列。
- 不临时重写匹配算法，不做 O(N²) 的 LLM 两两比较。
- 不把 `/profile`、`/me`、`/side` 合并成一个长页面。
- 不等待知乎 OAuth 才上线；先使用清楚标注的预览数据完成参赛闭环。
- 不把真实爬虫原文、Cookie、人物画像产物或 API Key 提交到 Git。
- 不在最后一天做大范围视觉重构或换技术栈。
