# 遇见 · 产品说明（提交材料）

> 发现一个值得聊一句的人。
> 知乎已经帮你发现值得看的内容；遇见帮你通过内容，发现一个值得聊一句的人。

## 一、问题

社交产品的匹配逻辑是「标签对标签」：年龄、职业、星座、兴趣标签。它回答的是"你们像不像"，回答不了"你们聊得来吗"。而真正让人想认识一个人的，往往是一篇回答里的一次坦诚、一个反复出现的疑问、一种看世界的方式——**这些标签永远装不下**。

## 二、方案

遇见不问你的标签，**读你写过的内容**：

1. **授权采集**：用户通过知乎 OAuth 登录，授权采集自己公开的创作内容（回答/文章），原文存档仅本人可见。
2. **两层理解**：
   - **长期理解**（规则层）：基于内容的向量画像，回答"你经常讨论什么"；
   - **完整画像**（AI 证据层）：两阶段 LLM 管线——先逐篇抽取"可公开的线索"，再综合成带证据链的画像：六维雷达 + 时间线 + 核心结论，每一条结论都能点开看到出处原文。
3. **方向性匹配**：不用对称的余弦相似度，而用**非对称的方向性分**（Directed Coverage + Generalized KL 散度）——"A 对 B 的感兴趣程度"与"B 对 A 的感兴趣程度"分别计算，取较小者作为双向匹配的保守估计。这是我们相对常见匹配产品的核心算法差异。
4. **一次可以拒绝的相遇**：推荐卡展示"为什么是 TA"（可解释证据）+ "为什么是这篇内容"（内容锚点）。双方都表达意愿才建立连接；任何一方都可以不回应。
5. **此刻与侧面**：不只有长期画像——"此刻"记录你现在的状态（疲惫/想走走/找同伴），强匹配时置顶为「此刻相遇」；"侧面"让你选择今天想从哪一面被看见。

## 三、隐私边界（设计原则，非事后补丁）

- **身份双轨隔离**：演示会话与真实会话是两套独立 Cookie + 数据池，互相不可见、不可混用；
- **内容原文仅本人可见**：采集原文存档只用于生成本人画像，不进入任何其他用户的数据面；
- **自愿公开**：完整画像默认私有；用户可以一键公开到「画像长廊」，也可以随时撤下（`shared_at` 开关）；
- **Demo 不用真人替代**：演示模式的候选池与真实池物理隔离，绝不虚构"已经匹配"的结论。

## 四、技术架构

- Next.js 16 + PostgreSQL（Drizzle ORM）+ 独立画像 Worker 的全栈基座；
- 知乎 OAuth 登录 + 内容采集（分页拉全，当前 120 条）；
- 画像管线：逐内容抽取（批量 + 失败重试 + 内容哈希缓存）→ 综合（流式输出，规避网关长请求超时）；
- 匹配管线：硬过滤 → 多路召回 → 方向性粗排 → LLM Rerank → 双向意愿状态机；
- 部署：Docker 多阶段构建 → 阿里云 ACR → Sealos 容器云；GitHub 全量开源（MIT）。

## 五、演示指引

**演示模式**（无需登录，预置数据完整）：首页 → 体验演示 → 画像 → 此刻 → 侧面 → 遇见 → 查看推荐卡（可解释证据）→ 想认识 → 双向连接。

**真实模式**（知乎账号登录）：登录后自动采集内容 → 生成个人完整画像（六维 + 时间线 + 证据链）→ 自愿公开到画像长廊 → 与其他真实用户相遇匹配。

## 六、团队

三人小组 + AI 协作开发：Present Self（此刻/表达）、Encounter & Matching（相遇与匹配算法）、Side & Platform（侧面/长廊/平台集成）。
