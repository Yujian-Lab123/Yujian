# Present Self 结构化存储与到期契约（待 D 确认）

本文件为契约 Issue 草案，尚未代表已批准的 API。

## 本分支可用行为

- 使用既有 `POST /api/me/current-state { text, mood }`。
- 当前状态、最近困惑、活动意愿、社交需求以带标签的可读文字合成 `text`，上限 200 字；保持 `GET /api/me` 的返回格式。
- 心情仍独立保存为 `mood`；刷新可查看完整记录，不将旧文字反解析成结构化字段。
- 连接意愿使用既有 `POST /api/me/toggle { enabled }`，独立、立即保存。
- 有效期控件明确标记未接入，不承诺自动到期。

## 请 D 发起的契约 / 迁移 Issue

建议追加字段：`state`、`confusion`、`activityIntent`、`socialNeed`、`validForHours`（建议 1 / 4 / 24 / 72 小时），保留 `text`、`mood` 兼容现有消费者。

- `GET /api/me` 的 `currentState` 追加上述结构化字段、`expires_at` 与 `expired`；旧记录字段为空，不推断默认意愿。
- 服务端校验枚举与文字长度，由服务端保存时间计算 `expiresAt`，状态写入与向量更新须原子完成。
- D 的 `getUserVectors` 与 C 的推荐逻辑需要屏蔽到期状态；当前代码始终使用最新记录，单独填 `expiresAt` 无法保证匹配停止使用。
- 确认有效期只影响当下状态，还是同时关闭连接意愿；建议连接开关保持独立，需产品负责人决定。
- 用户原文仍仅本人可读取。C 仅消费有效向量，不读取推荐对象原文。
- 明确空状态、未知枚举、非法有效期、登录失效的错误响应；延续 `{ ok: false, error, loginRequired? }`。

## 联调验收

1. 首次记录与旧数据兼容，保存后刷新七项信息保持一致。
2. 1 小时状态在到期边界失效，刷新页面和推荐计算一致。
3. 新状态覆盖旧状态；并发保存、失败回滚不造成状态与向量不一致。
4. 未登录及不同用户会话无法读取或修改他人记录。
